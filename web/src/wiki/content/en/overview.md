# Overview

This wiki describes the controlled *in vitro* experiment that compares decompositions of Java monoliths into microservices generated by a general-purpose large language model (LLM) with those of hierarchical clustering (AH) and those of a random partition with the same number of services *K*. AH is the abbreviation used throughout the study, from the Portuguese *agrupamento hierárquico*. The pages follow the code of the `monosplit` package and the experimental plan (roteiro) of 31 October 2026.

The final experiment was run on 6 November 2026 with the model `gpt-6.1-sol` (profile `gpt-6.1-sol-high`), on the four applications and in both variants. Its results are on the [Results](#/results) page (experiment `final`). These pages describe the design, the instruments and the decisions taken along the way; they do not discuss the results. The dry run with the `fake` client, which calls no model, only checks the instruments: its numbers are not data.

## Goal

The goal follows the GQM (Goal-Question-Metric) template.

| Element | Definition |
|---|---|
| Analyse | decompositions of monolithic applications into microservices generated by a general-purpose LLM |
| for the purpose of | evaluating them against hierarchical clustering (AH) and a random partition |
| with respect to | structural quality, measured by structural modularity (SM), interface number (IFN), inter-partition communication (ICP) and non-extreme distribution (NED) |
| from the point of view of | the software architect in charge of the migration |
| in the context of | four open-source Java applications used as benchmarks in the literature, in an *in vitro* experiment |

## Research questions

- **RQ1.** Do decompositions generated by a general-purpose LLM have higher structural quality than those of hierarchical clustering?
- **RQ2.** Do decompositions generated by a general-purpose LLM have higher structural quality than those of a random partition with the same number of services?

## Workflow

```
Java monolith, pinned to a commit
   │  build and bytecode reading (javap)
   ▼
Static call graph between classes
   │
   ├──────────────────────┬────────────────────────┐
   ▼                      ▼                        ▼
LLM (chooses K)     AH cut at K            Random partition with K
   │                      │                        │
   └──────────────────────┴────────────────────────┘
   │  same graph, same scripts
   ▼
SM, IFN, ICP and NED of each partition
   │
   ▼
Paired differences LLM − control  →  statistical analysis
```

The baseline article is Weerasinghe et al. (2026), which compared nine decomposition approaches on the same four applications with the same metrics, without hypothesis tests or reports of run-to-run variation.
